STEP 2 — CONFIG FORMAT (MANDATORY)
modules/oversys/v1/config_v1.md must be markdown with a single fenced code block like:

```oversys
<YAML here>
````

The YAML must define:

* oversys: 1
* system.id
* events: list of event types (only used for validation)
* rules.transitions: from + event + to (simple state machine)
* rules.invariants: at least:

  * only_lease_owner_can_progress
  * lease_must_be_valid_for_progress
* rules.lease: duration_ticks and clock_event (Tick)
* subscriptions: minimal declarative auto-handler that on WorkRequested for a specific workType emits WorkClaimed, WorkStarted, WorkCompleted (in order)
* scenarios: at least 2

  1. happy_path: user emits WorkRequested; auto_process_subscriptions=true; assert work reaches Completed (or Accepted if you add acceptance)
  2. lease_expires: claim work; advance time via Tick beyond lease; attempt WorkStarted; expect invariant failure

Keep it minimal: use only these event types:
WorkRequested, WorkClaimed, WorkStarted, WorkCompleted, WorkFailed, WorkAccepted (optional), Tick

STEP 3 — SIMULATION ENGINE (MINIMAL)
Implement a deterministic simulator:

* Maintain “now_tick” integer (starts from scenario given.now_tick or 0)
* Maintain WorkState map by workId:

  * status (Requested/Claimed/InProgress/Completed/Accepted/Failed/etc)
  * leaseOwner, leaseUntil, leaseNonce (nonce can be simple increment integer)
* Process steps in scenario:

  * emit: adds event to trace and applies transitions + invariants
  * auto_process_subscriptions: when true, after each emit, repeatedly apply subscriptions until no more apply (cap with a reasonable max like 50 to avoid loops)
  * Tick: sets now_tick = payload.t
* Lease rules:

  * When WorkClaimed occurs, set leaseUntil = now_tick + duration_ticks, leaseOwner = actor, leaseNonce += 1
  * WorkStarted/WorkCompleted/WorkFailed require:

    * actor == current leaseOwner
    * now_tick < leaseUntil
  * If invariant fails, record scenario failure with invariant id and stop scenario

Transitions:

* apply transition if rule matches current status + event type
* if no transition rule matches, treat as error (scenario fail)

Subscriptions:

* support only a minimal predicate:

  * listens_for: WorkRequested
  * when.workType equals some declared id
  * emits: [WorkClaimed, WorkStarted, WorkCompleted] with actor fixed to e.g. worker:projection
* For emitted subscription events, use same workId and respect invariants.

Assertions:

* allow assert of final status:

  * assert: state_of.workId equals <Status>
* allow assert_fail: <invariant_id>
